## 一次用户操作，对应一次编辑事务

> **参考源与适用范围：** 参考 [MouseManager.java](../../src/com/lushprojects/circuitjs1/client/MouseManager.java) 的 onMouseDown、mouseDragged、endDrag、[UndoManager.java](../../src/com/lushprojects/circuitjs1/client/UndoManager.java) 的 pushUndo、doUndo、doRedo。借鉴拖动生命周期与快照历史；预览隔离、统一校验、原子提交和一次操作一次历史是本方案新增约定。

一次拖动可能修改道岔、相连轨道端点及派生几何，用户应能一次撤销整个操作。

```text
鼠标按下：记录原始文档，启动拖动会话
鼠标移动：始终根据原始数据与总位移计算预览
鼠标释放：维护连接 → 验证候选文档 → 原子提交 → 写入历史
Esc 取消：丢弃预览，保留原始文档
```

避免每次 mousemove 都向历史栈追加记录；也避免将“总位移”反复累加到已经改变的数据上。

建议文档编辑模块向工具暴露少量意图操作，例如移动、连接、删除和修改属性。它在内部完成校验与历史管理，工具不用学习一串必须按顺序调用的维护函数。

第一版采用完整文档快照即可，但必须保证：

- 无变化的点击不产生历史记录。
- 撤销后有新提交时清空重做栈。
- 失败或取消的操作不改变文档和历史。
- 自动恢复保存已提交文档，不保存未完成预览。
- 纯缩放和平移默认不作为文档修改；是否随撤销恢复视图单独约定。

## 最小提交协议

```text
execute(intent, baseRevision)
  → 检查当前 revision 与操作上下文
  → 生成候选并维护引用
  → 验证候选
  → 无变化：返回 unchanged，不改历史
  → 成功：保存旧快照、替换文档、推进 revision、清空 redo
  → 通知渲染及恢复模块
```

失败返回诊断，保留旧文档、revision 和历史。Undo/redo 同样通过一个受控入口切换快照，清理引用旧对象的悬停、预览和选择状态。

## 第一版历史策略

采用完整文档快照，设置可配置的记录数或内存预算。预览、视图及运行态不混入设计历史；如需恢复视图，可作为附加元数据保存，不能改变文档语义。

保存状态用内容身份或保存基准判断，不能简单在 undo 后一律设为干净。撤销回保存版本应清除未保存提示；撤销到其他版本仍有未保存修改。自动恢复记录当前已提交版本，与历史容量独立。

## 验收

- 一次移动及关联修改只需一次撤销，重做完整恢复。
- 点击、取消、校验失败和无变化候选不影响历史及重做栈。
- 撤销到保存内容时显示已保存，其他版本显示未保存。
- 历史淘汰不会改变当前文档，加载新文档不保留旧对象的预览引用。
