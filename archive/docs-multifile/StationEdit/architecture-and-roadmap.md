# StationEdit：范围、代码组织与开发路线

本文是站场图编辑器的建议设计，尚未在仓库中实现。TypeScript 风格示例用于说明结构，不限定技术选型。各节注明参考源码与新增设计。

[文档导航](../README.md) · [对应 CircuitJS 实现](../architecture.md)

## 先明确第一版要完成什么

> **参考源与适用范围：** 本节为站场图第一版的范围建议，并非 CircuitJS 已实现的铁路功能。功能闭环参考 [MouseManager.java](../../src/com/lushprojects/circuitjs1/client/MouseManager.java) 的 创建、选择和拖动流程、[UndoManager.java](../../src/com/lushprojects/circuitjs1/client/UndoManager.java) 的 撤销与恢复。

第一版建议支持轨道线段、简单道岔、信号机和文字，形成以下闭环：

1. 放置图元，设置名称、位置和朝向。
2. 选择、移动、调整轨道端点。
3. 显式连接轨道与道岔端口。
4. 保存、重新打开、撤销和重做。
5. 检查连接引用有效性、设备编号重复和未连接端口。

第一版的道岔与轨道几何是示意表达。这里的编辑模型不构成完整的铁路业务规则；进路、联锁、占用等能力需要后续根据具体需求单独建模。

## 建议的代码组织

> **参考源与适用范围：** 职责拆分参考 [CirSim.java](../../src/com/lushprojects/circuitjs1/client/CirSim.java) 的 模块组织 及 MouseManager、UIManager、UndoManager 等文件。这里给出的目录、文档编辑接口和数据归属是新项目建议，不是当前仓库的目录现状。

```text
src/
  document/       图元记录、文档编辑、引用维护和校验
  elements/       轨道、道岔、信号机、文字的几何与行为
  geometry/       坐标变换、包围盒、距离、旋转、吸附
  interaction/    选择、放置、拖动工具和预览会话
  render/         画布、视图、绘制次序和高亮
  history/        快照、撤销和重做
  io/             文件解析、版本检查、保存和恢复
  ui/             工具栏、属性面板和提示
```

以上是职责划分，起步时可以用少量文件承载，不需要每个概念都增加接口、工厂和独立模块。

后续确实需要路径分析时，再增加 topology 模块，从文档构建图并提供路径查询；分析结果可以重建，文档中的显式连接仍是事实来源。

## 分阶段开发与验收

> **参考源与适用范围：** 本节为根据前述模块依赖整理的实施顺序与完成条件，没有直接对应的 CircuitJS 开发计划。每阶段的实现参考见相关设计章节。

| 阶段 | 实现内容 | 完成条件 |
| --- | --- | --- |
| 1：线段闭环 | 轨道绘制、选择、移动、端点调整 | 改变位置后绘制和命中一致；无零长度线段 |
| 2：视图交互 | 平移、缩放、网格、命中容差 | 缩放不改图元数据；鼠标中心缩放；不同缩放下容易选中 |
| 3：多种图元 | 道岔、信号机、文字、属性面板 | 通用选择和移动无需为每种设备增加专门分支 |
| 4：历史与文件 | 快照、撤销、重做、保存加载 | 一次拖动一次撤销；保存加载保留 ID、属性和几何 |
| 5：连接维护 | 端口吸附、显式连接、关联清理 | 道岔移动带动相连轨道端点；删除无悬空引用 |
| 6：完整校验 | 编号、连接、几何与关联检查 | 错误可定位到图元；无效修改不破坏已提交文档 |

先用“一个道岔、三条轨道、一个信号机、一段文字”作为样例文档贯穿各阶段，不必从大量设备类型开始。

## 最值得验证的行为

> **参考源与适用范围：** 本节为本站场方案的验收建议，不声称仓库已有对应自动化测试。被验证行为的源码参考与设计差异见 [坐标系统](coordinate-system.md)、[连接拓扑](topology-and-connections.md)、[编辑事务](edit-transactions.md) 和 [保存、复制与删除](persistence-and-copy.md)。

将验证重点放在接口行为和跨图元一致性：

- 道岔旋转后，端口、绘制与命中位置一致。
- 鼠标中心缩放前后，指向的图纸位置保持一致，允许实现精度范围内误差。
- 移动已连接道岔后，相连轨道端点更新；一次撤销恢复全部变化。
- 拖动取消或提交失败后，文档和历史没有变化。
- 复制一组连接设备后，副本只引用应复制的对象。
- 删除轨道后，连接和信号关联按规则清理；撤销完整恢复。
- 保存再加载后，ID、业务属性和连接等价，不要求缓存或字段顺序相同。
- 加载损坏文件时，原文档保留。

几何、引用维护、事务和保存加载适合自动化验证；画面清晰度、手柄可发现性和拖动手感需要实际操作检查。

## 数据流与模块依赖

```text
输入适配 → 工具/命令 → 文档编辑模块 → 新文档与 revision
                    ↘ 预览会话       ↘ 校验/历史/自动恢复
新文档 + 几何 + 视图 + 会话 + 可选运行态 → 渲染
```

图元几何和文档规则不依赖 DOM、文件系统或整个应用实例。存储、宿主通信、桌面文件与渲染是外围能力；只有实际需要替换的实现才引入适配接口，避免预先设计完整插件平台。

异步解析、布局和保存通过 revision/requestId 关联到发起时的文档。UI 不能因晚返回的任务把新文档覆盖为旧版本。

## 后续主题的实施顺序

- 第一版必需：图元、坐标、工具、选择、绘制、属性、命令、事务、文件、校验和基本测试。
- 编辑闭环稳定后：恢复、模板、搜索、打印导出、性能基准、触摸与键盘补充。
- 按真实需求加入：自动布线、路径分析、运行演示、时间线、外部接口、桌面与离线。

这是一份完整技术路线，不要求第一版同时交付所有扩展。每个专题的验收条件与参考源码见 [总导航](../README.md)。
