## 构建约定

依赖版本、运行时版本和锁文件进入版本控制。生产产物由干净源码构建，静态资源与脚本使用统一基址，支持部署到子路径；不要把开发机绝对路径写进资源清单。

起步先实现单页 Web 版本。Canvas、文档模型和图元逻辑不依赖部署平台；桌面能力通过需要时才引入的适配器提供。

## 流水线

安装锁定依赖 → 编译/类型检查 → 核心测试 → 打包 → 资源完整性检查 → 预览主流程 → 生成可追踪产物。记录 commit、应用版本和工程 schema 版本。

发布前准备具体产物与验证结果，发布执行单独按用户授权处理。开发文档描述流程不等于执行部署。

## 资源验证

检查入口、字体、符号库、语言、示例和可选 worker 均可从最终产物访问；确认资源更新策略与缓存版本匹配。保留最近可用产物，回退应用时仍需处理较新工程文件的版本提示。

## 验收

干净环境可重复构建；子路径预览无资源 404；最终产物能创建、保存再加载站场；不含恢复草稿或开发测试数据；构建日志能区分编译失败和资源缺失。
