# 站场图编辑器：技术实现与开发指南

本文面向学习 CircuitJS 并开发铁路信号站场图编辑器的开发者。从图元抽象展开，覆盖坐标、几何、渲染、交互、拓扑、文件、运行扩展、性能、验证与交付，并给出数据结构、模块职责、流程和验收条件。

本文只维护站场图编辑器的建议设计，尚未在仓库中实现。代码使用 TypeScript 风格表达结构，不代表新项目必须采用 TypeScript。

各节的“参考源与适用范围”标明所借鉴的源码、关键方法和新增设计；源码链接相对于本文，可直接打开仓库文件。

现有软件的实现与源码阅读入口见 [CircuitJS 图元与编辑器实现](../circuitjs-element-implementation.md)。

## 1. 先明确第一版要完成什么

> **参考源与适用范围：** 本节为站场图第一版的范围建议，并非 CircuitJS 已实现的铁路功能。功能闭环参考 [MouseManager.java](../../src/com/lushprojects/circuitjs1/client/MouseManager.java) 的 创建、选择和拖动流程、[UndoManager.java](../../src/com/lushprojects/circuitjs1/client/UndoManager.java) 的 撤销与恢复。

第一版建议支持轨道线段、简单道岔、信号机和文字，形成以下闭环：

1. 放置图元，设置名称、位置和朝向。
2. 选择、移动、调整轨道端点。
3. 显式连接轨道与道岔端口。
4. 保存、重新打开、撤销和重做。
5. 检查连接引用有效性、设备编号重复和未连接端口。

第一版的道岔与轨道几何是示意表达。这里的编辑模型不构成完整的铁路业务规则；进路、联锁、占用等能力需要后续根据具体需求单独建模。

## 2. 统一的是能力，不是形状

> **参考源与适用范围：** 参考 [CircuitElm.java](../../src/com/lushprojects/circuitjs1/client/CircuitElm.java) 的 getPostCount、getPost、getNumHandles、drawHandles 和 [GraphicElm.java](../../src/com/lushprojects/circuitjs1/client/GraphicElm.java) 的 getPostCount。借鉴统一能力与子类差异；将锚点、手柄、端口分别建模是本站场方案的改进。

编辑器需要统一处理绘制、命中检测、选择、移动和保存，但不应要求所有图元拥有相同几何结构。

| 图元 | 持久化的几何输入 | 可编辑手柄 | 连接或关联 |
| --- | --- | --- | --- |
| 轨道线段 | 起点、终点 | 两个端点 | start、end 端口 |
| 简单道岔 | 锚点、朝向、左右开向、尺寸参数 | 移动、朝向控制 | common、normal、reverse 端口 |
| 信号机 | 位置、朝向 | 移动、朝向控制 | 关联轨道及面向方向 |
| 文字 | 位置、文本、字号 | 位置；需要时增加文本框手柄 | 无拓扑连接 |

三个概念必须分别表达：

- **锚点**：放置和移动图元的几何基准。
- **手柄**：用户可以拖动的编辑控制点。
- **端口**：业务连接的稳定标识及其位置。

手柄和端口可能在画面上重合，但职责不同。道岔三个端口不意味着可以独立拖动三个端口；文字可以有手柄，但没有轨道端口。

## 3. 先确定数据归谁所有

> **参考源与适用范围：** 参考 [CirSim.java](../../src/com/lushprojects/circuitjs1/client/CirSim.java) 的 elmList、transform 等状态、[CircuitElm.java](../../src/com/lushprojects/circuitjs1/client/CircuitElm.java) 的 几何字段与 selected。本节按文档、派生几何、会话、运行状态重新划分归属，是建议设计，现有代码并未完全这样分离。

建议采用“文档持有数据，图元逻辑解释数据”的方式。相比前期把所有能力放进基类，这种组织便于保存、撤销和独立验证。

| 数据 | 所有者 | 是否进入工程文件 |
| --- | --- | --- |
| ID、名称、类型、位置、设备属性 | 文档中的图元记录 | 是 |
| 端口之间的连接、信号机关联 | 文档 | 是 |
| 包围盒、符号轮廓、端口位置 | 由图元数据计算的几何结果 | 通常否 |
| 当前选择、悬停、拖动预览 | 编辑会话 | 否 |
| 缩放、平移、网格设置 | 视图状态 | 可作为可选视图配置保存 |
| 占用、信号显示等运行状态 | 后续运行状态模块 | 默认不写入静态设计数据 |

不要把包围盒与真实几何作为两套独立可修改的数据。几何改变后，应重新计算派生结果或使缓存失效。

选择集可由会话持有 `selectedIds: Set<ElementId>`，不把 selected 字段写入设备记录。删除、加载或撤销后，按当前文档清理不存在的 ID；悬停和预览也不继续引用已被替换的旧对象。

## 4. 稳定身份与最小模型

> **参考源与适用范围：** 几何与端点建模参考 [CircuitElm.java](../../src/com/lushprojects/circuitjs1/client/CircuitElm.java) 的 setPoints、getPost。稳定设备 ID、端口引用、Connection、轨道区段区分与信号关联结构均为本站场方案新增设计；这些类型不是从 CircuitJS 直接移植。

设备名称可修改，不能作为内部身份。文档引用应使用稳定 ID；端口 ID 在所属图元内部稳定。

```ts
type Point = { x: number; y: number };
type ElementId = string;

type TrackElement = {
  id: ElementId;
  kind: "track";
  name: string;
  start: Point;
  end: Point;
};

type TurnoutElement = {
  id: ElementId;
  kind: "turnout";
  name: string;
  anchor: Point;
  rotation: number; // 本示例约定弧度；UI 可以显示角度
  handedness: "left" | "right";
  length: number;
  branchOffset: number;
};

type SignalElement = {
  id: ElementId;
  kind: "signal";
  name: string;
  position: Point;
  rotation: number;
  attachment?: {
    trackId: ElementId;
    t: number; // 沿轨道 start → end 的归一化位置，范围 [0, 1]
    facing: "towardStart" | "towardEnd";
  };
};

type TextElement = {
  id: ElementId;
  kind: "text";
  position: Point;
  text: string;
  fontSize: number;
};

type DiagramElement =
  | TrackElement | TurnoutElement | SignalElement | TextElement;

type PortRef = { elementId: ElementId; portId: string };
type Connection = { id: string; a: PortRef; b: PortRef };

type StationDocument = {
  format: "stationedit";
  schemaVersion: 1;
  id: string;
  elements: DiagramElement[];
  connections: Connection[];
};
```

这里的 track 表示可绘制线段，尚未定义业务上的轨道区段。后续如果一个区段包含多条线段，应增加区段记录引用线段，避免让线段承担所有业务含义。

信号机的几何位置与 attachment 是独立数据。第一版可以约定轨道变形时保留 t，信号机符号仍由用户布置；若要自动随轨道移动，应另行明确偏移、方向与更新规则。

## 5. 图元逻辑的公共接口

> **参考源与适用范围：** 参考 [CircuitElm.java](../../src/com/lushprojects/circuitjs1/client/CircuitElm.java) 的 draw、move、movePoint、getMouseDistance、[ResistorElm.java](../../src/com/lushprojects/circuitjs1/client/ResistorElm.java) 的 具体方法重写。ElementBehavior、纯计算及返回新记录的约定为建议设计；CircuitJS 当前主要使用可变对象与继承。

第一版可以用一个类型注册表集中查找图元逻辑，不必同时建设复杂继承树与插件系统。

```ts
interface ElementBehavior<E extends DiagramElement> {
  geometry(element: E): ElementGeometry;
  draw(element: E, geometry: ElementGeometry, context: RenderContext): void;
  hitTest(element: E, point: Point, tolerance: number): HitResult | null;
  translate(element: E, delta: Point): E;
  editHandle(element: E, handleId: string, target: Point): E;
}
```

`ElementGeometry` 提供包围盒、手柄以及零个或多个端口；`RenderContext` 提供绘图能力和必要的显示信息，不传入整个应用对象。以上接口中的辅助类型应随实际功能定义，不必预先扩展为通用图形框架。

接口还必须说明行为约定：

- geometry、hitTest、draw 不修改文档；translate、editHandle 返回新记录。
- 坐标使用图纸坐标，数值必须有限；角度单位在模型内统一。
- 几何计算不依赖 Canvas，可在不启动界面的情况下验证。
- 非法编辑返回明确的失败结果或错误，不能静默留下部分修改。
- 文档模块负责更新关联图元，单个图元逻辑只计算自身变化。

如果实际使用 Java，可以采用抽象类加具体图元类实现相同约定。关键是调用者只需理解少量操作，几何细节集中在对应图元实现中。

## 6. 几何、命中与显示

> **参考源与适用范围：** 参考 [MouseManager.java](../../src/com/lushprojects/circuitjs1/client/MouseManager.java) 的 inverseTransformX/Y、transformX/Y、mouseSelect、setCircuitScale、[UIManager.java](../../src/com/lushprojects/circuitjs1/client/UIManager.java) 的 updateCircuit。固定屏幕命中容差、统一派生几何与道岔局部坐标是本方案的具体约定，不代表现有代码已全部实现。

推荐顺序：图元数据 → 几何结果 → 绘制与命中。包围盒、端口和符号轮廓应来自一致的几何定义。

### 坐标约定

建议明确四种坐标，避免把页面鼠标位置、高分屏像素和图纸位置混用：

| 坐标 | 用途 | 单位 |
| --- | --- | --- |
| local | 图元自身的符号、端口、轮廓 | 图元局部单位 |
| world | 整张图纸中的布局与拓扑几何检查 | 自定义图纸单位，不自动代表米 |
| screen | 相对画布内容左上角的显示位置 | CSS 像素 |
| device | Canvas 实际缓冲区位置 | 绘图缓冲区像素 |

```text
屏幕坐标 = 图纸坐标 × scale + translation
图纸坐标 = (屏幕坐标 - translation) / scale
```

图元位置保存图纸坐标，缩放和平移修改视图。Canvas 的设备像素比在渲染层处理；鼠标的 CSS 像素坐标不应再被重复乘设备像素比。

内部保留浮点数，所有输入必须有限，scale 必须大于零。第一版视图只支持均匀缩放和平移。模型中的角度使用弧度，坐标 X 向右、Y 向下，正角度视觉上为顺时针。

例如图纸点 (100, 200)、scale=2、偏移 (50, 30)，对应显示点 (250, 430)，反变换应在误差范围内恢复原点。拖动时鼠标移动 20 CSS 像素，在此比例下对应 10 个图纸单位。

浏览器事件转画布显示坐标时，先取 `clientX - rect.left` 与 `clientY - rect.top`，其中 rect 是画布的 getBoundingClientRect 结果。此简式要求画布没有 border、padding 和额外 CSS 缩放或旋转；布局边框放在外层容器。如果事件适配器已经给出画布相对坐标，不再减一次偏移。

### 平移、缩放与高分屏

平移使用显示坐标差更新视图偏移；图元拖动则使用图纸坐标差。鼠标中心缩放先用旧视图取得固定图纸点，再计算：

```ts
const world = screenToWorld(mouse, viewport);
const scale = Math.max(minScale,
  Math.min(maxScale, viewport.scale * zoomFactor));
const nextViewport = {
  scale,
  offsetX: mouse.x - world.x * scale,
  offsetY: mouse.y - world.y * scale,
};
```

倍率必须为有限正数，滚轮输入先在适配层归一化。拖动预览期间第一版固定视图；允许边拖边平移时，需要重新定义拖动基准，不能直接累加旧偏移。

Canvas 的 CSS 尺寸保持显示尺寸，width/height 设为显示尺寸乘 dpr 后取整；绘图变换为：

```ts
ctx.setTransform(dpr * v.scale, 0, 0, dpr * v.scale,
                 dpr * v.offsetX, dpr * v.offsetY);
```

改变 Canvas width/height 会重置上下文状态，仅在缓冲区尺寸或 dpr 改变时设置，并重建变换、字体与线型。单位变换下清空整个缓冲区，再应用图纸变换；固定像素手柄可在仅含 dpr 的显示坐标变换下绘制。零尺寸布局暂缓绘制。

### 局部坐标与吸附公式

道岔局部点绕锚点旋转并平移：

```text
worldX = anchorX + localX × cosθ - localY × sinθ
worldY = anchorY + localX × sinθ + localY × cosθ
```

反向转换令 dx=worldX-anchorX、dy=worldY-anchorY：

```text
localX =  dx × cosθ + dy × sinθ
localY = -dx × sinθ + dy × cosθ
```

旋转后的轴对齐包围盒由局部包围盒全部角点变换后取极值得到，不能只平移原矩形。

网格吸附可用 `Math.round(value / gridSize) * gridSize`，gridSize 必须为有限正数。半格负数的舍入方向需明确；Math.round 的半格策略不是远离零的对称舍入。移动选择集时吸附统一锚点或总位移，保持相对布局。

将 worldToScreen、screenToWorld、localToWorld、worldToLocal、snapToGrid 集中在 geometry 模块。验证往返误差、负坐标、鼠标中心缩放、dpr 变化和固定像素容差。

### 命中流程

1. 将鼠标转换成图纸坐标。
2. 用扩大了容差的包围盒筛选候选图元。
3. 对候选进行点到线段、符号轮廓或文字区域的精确检测。
4. 返回图元 ID、命中部位、手柄或端口 ID、距离。
5. 按当前工具的优先级决定结果。

容差先用屏幕像素定义，再计算 `图纸容差 = 屏幕容差 / scale`，让缩放后的点击难度保持稳定。当前选中图元的手柄可优先于主体；重叠对象还需明确绘制层级及选取顺序。

例如固定 6 CSS 像素容差，scale 为 0.5、1、2 时，图纸容差分别为 12、6、3，不再乘 dpr。

第一版可遍历所有图元。出现实测性能问题后，再增加空间索引和视口裁剪。

### 道岔几何

在局部坐标系中定义公共端、直向端和分支端，然后统一旋转、平移到图纸坐标。端口位置、符号绘制和命中轮廓使用同一组几何结果。

不要在绘制函数、命中函数和端口函数中分别写三套道岔尺寸公式。

## 7. 显式连接与拓扑

> **参考源与适用范围：** 网络构建思路参考 [SimulationManager.java](../../src/com/lushprojects/circuitjs1/client/SimulationManager.java) 的 makeNodeList、calculateWireClosure；几何寻路参考 [WireRouter.java](../../src/com/lushprojects/circuitjs1/client/WireRouter.java) 的 routeWire。持久化显式连接、端口容量、道岔通路和联动移动规则属于本站场新增设计。

图形相交不自动代表连接。可以在用户靠近端口时提供吸附预览，确认后创建 Connection。

第一版建议约定：

- 连接只引用实际存在的图元及端口。
- 每个端口最多连接另一个端口；需要分支时使用明确的分支设备。
- 禁止重复连接和端口自连接。
- 已连接端口的图纸位置应在约定容差内重合。
- 吸附失败或几何约束不满足时，整个操作失败，不保留半条连接。

这些是学习版编辑器的设计约束，可随支持的设备类型调整。

### 移动已连接设备

推荐第一版规则：移动道岔时，跟随更新直接连接的轨道端点；移动会导致无效几何时拒绝提交。暂不支持的连接组合应明确拒绝或由用户先断开。

移动工具只提交“移动哪些对象、移动多少”的意图，由文档编辑模块完成图元更新、连接维护、有效性检查和历史提交。避免每个鼠标事件调用处都自行维护关联。

### 道岔通路

common、normal、reverse 三个端口的存在，不表示三个端口之间始终可通行。未来的路径分析需要另外定义设备内部允许的通路及其条件。

自动布线解决几何布局问题；沿站场拓扑寻找路径解决连接与通路问题，应使用不同入口。

## 8. 一次用户操作，对应一次编辑事务

> **参考源与适用范围：** 参考 [MouseManager.java](../../src/com/lushprojects/circuitjs1/client/MouseManager.java) 的 onMouseDown、mouseDragged、endDrag、[UndoManager.java](../../src/com/lushprojects/circuitjs1/client/UndoManager.java) 的 pushUndo、doUndo、doRedo。借鉴拖动生命周期与快照历史；预览隔离、统一校验、原子提交和一次操作一次历史是本方案新增约定。

一次拖动可能修改道岔、相连轨道端点及派生几何，用户应能一次撤销整个操作。

```text
鼠标按下：记录原始文档，启动拖动会话
鼠标移动：始终根据原始数据与总位移计算预览
鼠标释放：维护连接 → 验证候选文档 → 原子提交 → 写入历史
Esc 取消：丢弃预览，保留原始文档
```

避免每次 mousemove 都向历史栈追加记录；也避免将“总位移”反复累加到已经改变的数据上。

建议文档编辑模块向工具暴露少量意图操作，例如移动、连接、删除和修改属性。它在内部完成校验与历史管理，工具不用学习一串必须按顺序调用的维护函数。

第一版采用完整文档快照即可，但必须保证：

- 无变化的点击不产生历史记录。
- 撤销后有新提交时清空重做栈。
- 失败或取消的操作不改变文档和历史。
- 自动恢复保存已提交文档，不保存未完成预览。
- 纯缩放和平移默认不作为文档修改；是否随撤销恢复视图单独约定。

## 9. 保存、复制和删除

> **参考源与适用范围：** 参考 [XMLSerializer.java](../../src/com/lushprojects/circuitjs1/client/XMLSerializer.java) 的 dumpCircuit、[CircuitLoader.java](../../src/com/lushprojects/circuitjs1/client/CircuitLoader.java) 的 readCircuit、[CommandManager.java](../../src/com/lushprojects/circuitjs1/client/CommandManager.java) 的 copyOfSelectedElms、doPaste、doDelete。版本校验、稳定 ID 重映射、轨道删除后的信号关联清理和加载失败保留文档属于本站场方案。

### 保存加载

工程文件保存 schemaVersion、图元和连接，派生几何加载后重新计算。加载步骤建议为：

1. 解析文件并检查格式版本。
2. 检查字段类型、有限数值、ID 唯一性和设备属性范围。
3. 检查端口引用、信号关联和连接约束。
4. 完成后整体替换当前文档。

加载失败保留原文档，并报告可定位的原因。未知类型或不支持的版本应明确报错，避免静默丢失设备。

### 复制粘贴

- 为副本生成新的图元 ID 和连接 ID。
- 复制选区内部的连接，并通过旧 ID → 新 ID 映射更新引用。
- 默认不复制指向选区外设备的连接。
- 信号关联指向选区内轨道时重新映射；指向选区外轨道时，第一版清除关联并给出提示。
- 保持副本的相对位置，并作为一次事务提交。

### 删除

- 删除图元时，同时删除引用其端口的连接。
- 删除轨道时，清除相关信号机的 attachment，保留信号机符号并提示待重新关联。
- 整组删除及关联清理必须可以一次撤销。

这些规则应集中在文档编辑模块，不能只在键盘 Delete 的处理函数中实现，否则右键删除或其他入口容易遗漏。

## 10. 建议的代码组织

> **参考源与适用范围：** 职责拆分参考 [CirSim.java](../../src/com/lushprojects/circuitjs1/client/CirSim.java) 的 模块组织 及 MouseManager、UIManager、UndoManager 等文件。这里给出的目录、文档编辑接口和数据归属是新项目建议，不是当前仓库的目录现状。

```text
src/
  document/       图元记录、文档编辑、引用维护和校验
  elements/       轨道、道岔、信号机、文字的几何与行为
  geometry/       坐标变换、包围盒、距离、旋转、吸附
  interaction/    选择、放置、拖动工具和预览会话
  render/         画布、视图、绘制次序和高亮
  history/        快照、撤销和重做
  io/             文件解析、版本检查、保存和恢复
  ui/             工具栏、属性面板和提示
```

以上是职责划分，起步时可以用少量文件承载，不需要每个概念都增加接口、工厂和独立模块。

模块之间的数据流建议为：

```text
输入适配 → 工具/命令 → 文档编辑模块 → 新文档与 revision
                    ↘ 预览会话       ↘ 校验、历史、自动恢复
新文档 + 派生几何 + 视图 + 会话 + 可选运行态 → 渲染
```

图元几何和文档规则不依赖 DOM、文件系统或整个应用实例。存储、宿主通信和桌面文件能力放在外围，只有实际需要替换实现时才引入适配接口。异步解析、布局和保存关联发起时的 revision/requestId，晚返回的旧任务不得覆盖新文档。

后续确实需要路径分析时，再增加 topology 模块，从文档构建图并提供路径查询；分析结果可以重建，文档中的显式连接仍是事实来源。

## 11. 分阶段开发与验收

> **参考源与适用范围：** 本节为根据前述模块依赖整理的实施顺序与完成条件，没有直接对应的 CircuitJS 开发计划。每阶段的实现参考见相关设计章节。

| 阶段 | 实现内容 | 完成条件 |
| --- | --- | --- |
| 1：线段闭环 | 轨道绘制、选择、移动、端点调整 | 改变位置后绘制和命中一致；无零长度线段 |
| 2：视图交互 | 平移、缩放、网格、命中容差 | 缩放不改图元数据；鼠标中心缩放；不同缩放下容易选中 |
| 3：多种图元 | 道岔、信号机、文字、属性面板 | 通用选择和移动无需为每种设备增加专门分支 |
| 4：历史与文件 | 快照、撤销、重做、保存加载 | 一次拖动一次撤销；保存加载保留 ID、属性和几何 |
| 5：连接维护 | 端口吸附、显式连接、关联清理 | 道岔移动带动相连轨道端点；删除无悬空引用 |
| 6：完整校验 | 编号、连接、几何与关联检查 | 错误可定位到图元；无效修改不破坏已提交文档 |

先用“一个道岔、三条轨道、一个信号机、一段文字”作为样例文档贯穿各阶段，不必从大量设备类型开始。

## 12. 最值得验证的行为

> **参考源与适用范围：** 本节为本站场方案的验收建议，不声称仓库已有对应自动化测试。被验证行为的源码参考与设计差异见第 6 至 9 节。

将验证重点放在接口行为和跨图元一致性：

- 道岔旋转后，端口、绘制与命中位置一致。
- 鼠标中心缩放前后，指向的图纸位置保持一致，允许实现精度范围内误差。
- 移动已连接道岔后，相连轨道端点更新；一次撤销恢复全部变化。
- 拖动取消或提交失败后，文档和历史没有变化。
- 复制一组连接设备后，副本只引用应复制的对象。
- 删除轨道后，连接和信号关联按规则清理；撤销完整恢复。
- 保存再加载后，ID、业务属性和连接等价，不要求缓存或字段顺序相同。
- 加载损坏文件时，原文档保留。

几何、引用维护、事务和保存加载适合自动化验证；画面清晰度、手柄可发现性和拖动手感需要实际操作检查。

## 13. 设计自查

> **参考源与适用范围：** 本节为评估本站场图元抽象的设计问题；“绝缘节”是扩展场景，未在本文中实现。公共约定的源码对照为 [CircuitElm.java](../../src/com/lushprojects/circuitjs1/client/CircuitElm.java) 的 图元公共方法。

新增一种“绝缘节”图元时，检查以下问题：

1. 是否主要增加数据、几何、画法、属性与类型注册？
2. 现有选择、移动、删除、撤销是否仍然可用？
3. 是否被迫填写无意义的第二端点或电气字段？
4. 如果它需要切分轨道，能否将切分与引用更新作为一次事务提交？
5. 保存加载能否保留它的身份与关联？

公共抽象应隐藏重复的编辑复杂度，同时允许设备表达真实差异。出现实际差异时再扩展接口，避免为了可能出现的设备提前搭建复杂框架。

### 设备族与新增类型的接入

> **参考源与适用范围：** 类别共性参考 [ChipElm.java](../../src/com/lushprojects/circuitjs1/client/ChipElm.java)、[GateElm.java](../../src/com/lushprojects/circuitjs1/client/GateElm.java) 和 [GraphicElm.java](../../src/com/lushprojects/circuitjs1/client/GraphicElm.java)，资源生命周期参考 [AudioInputElm.java](../../src/com/lushprojects/circuitjs1/client/AudioInputElm.java)。下表是站场扩展分类建议，不增加第一版范围。

| 设备族 | 初始或后续类型 | 必须表达的差异 |
| --- | --- | --- |
| 轨道几何 | 线段，后续按需增加折线 | 端点、走向、连接 |
| 连接设备 | 简单道岔，后续复杂交叉设备 | 稳定端口与内部条件通路 |
| 信号设备 | 简单信号机 | 朝向、轨道关联、显示配置 |
| 分界与辅助标记 | 绝缘节、边界 | 业务作用、切分及关联 |
| 文字与装饰 | 文字、框线、底图 | 布局和资源，不参与轨道通行 |

新增类型按以下顺序落地：

1. 定义持久字段、版本和默认值。
2. 定义局部几何、端口与手柄。
3. 实现绘制、命中及支持的变换。
4. 接入属性、注册表与放置工具。
5. 定义连接兼容、内部通路和删除规则。
6. 验证文件往返、复制、撤销与样例。

设备语义应有明确类型，不用任意 shape 加字符串属性代替。

底图和图标通过资源 ID 引用，保存时明确嵌入或外链。缺失资源保留占位和设备记录，不在每次 draw 中请求网络，也不把临时内存缓存当作工程备份。新增设备若切分轨道，需同时处理原轨道 ID、区段归属和信号关联，整次放置作为一个事务。

## 14. 鼠标交互与工具状态机

> **参考源与适用范围：** 参考 [MouseManager.java](../../src/com/lushprojects/circuitjs1/client/MouseManager.java) 的 mouseMode、tempMouseMode、onMouseDown、mouseDragged、onMouseUp、endDrag、onMouseOut，以及 [UndoManager.java](../../src/com/lushprojects/circuitjs1/client/UndoManager.java) 的快照历史。显式状态、指针捕获、隔离预览、取消回滚及统一事务提交均为本站场方案新增设计。

### 工具与状态分别表示什么

工具回答“用户准备做什么”，状态回答“这次操作进行到了哪一步”。选择轨道工具不等于已经开始画轨道。

```text
工具：选择、画轨道、放道岔、放信号机、平移
状态：等待、按下待判定、拖动预览
```

第一版每次只允许一个指针手势；按下前可以切换工具，手势中切换工具先取消当前预览。按下时固定本次手势的目标和模式，不因鼠标经过其他设备而换目标。

### 输入、工具、文档各做什么

| 模块 | 职责 |
| --- | --- |
| 输入适配 | 事件坐标转换、pointerId、鼠标键、修饰键、指针捕获 |
| 工具 | 判断当前意图，管理状态和预览，提交编辑意图 |
| 几何与命中 | 返回候选目标、手柄、端口及吸附结果 |
| 文档编辑 | 维护连接、验证候选文档、原子提交和历史记录 |
| 渲染 | 绘制已提交文档、候选预览及交互提示 |

不要让每种图元各自注册鼠标事件。工具根据命中结果调用图元行为和文档编辑入口。

### 状态转换表

| 当前状态 | 输入 | 处理 | 下一状态 |
| --- | --- | --- | --- |
| 等待 | 主按钮按下 | 固定目标，记录原始文档、起始点和 pointerId，尝试捕获指针 | 按下待判定 |
| 按下待判定 | 移动未超过阈值 | 保留点击候选，不提交几何修改 | 按下待判定 |
| 按下待判定 | 移动超过阈值 | 根据工具与命中部位启动预览 | 拖动预览 |
| 按下待判定 | 主按钮释放 | 执行工具的点击行为，不创建零长度轨道 | 等待 |
| 拖动预览 | 指针移动 | 根据起始数据和总位移重算候选，显示吸附及无效原因 | 拖动预览 |
| 拖动预览 | 主按钮释放 | 以释放位置重算最终候选，验证并提交；失败则丢弃候选 | 等待 |
| 手势进行中 | Esc、pointercancel、窗口失焦或异常捕获丢失 | 丢弃预览，释放资源，保留已提交文档 | 等待 |

拖动阈值用 CSS 像素定义，例如先取 4 像素，再根据操作体验调整。有效性与最小轨道长度用图纸单位表达，两者不是同一个阈值。

### 选择工具的命中分发

建议优先考虑当前选中对象的手柄，其次主体，最后空白。连接工具则优先考虑兼容端口；命中优先级应与当前工具有关。

- 点中主体并释放：更新选择集；按住 Shift 时切换该图元的选择状态。
- 点中已选主体并拖动：移动当前选择集。
- 点中未选主体并拖动：以该图元为新的移动目标。
- 点中允许调整的手柄并拖动：进入对应几何调整。
- 空白处点击：清空选择；空白处拖动：框选，第一版采用包围盒完全包含规则。
- 拖动过程中保持命中目标固定，悬停变化只用于连接吸附等明确的候选查询。

几何预览取消不应遗留临时选择效果；手势记录开始时的选择集，取消时恢复。普通点击选择不进入文档撤销历史。

### 场景一：画一条轨道

```text
选中轨道工具
  → 按下：获取图纸起点，优先吸附可用端口，其次吸附网格
  → 拖动：计算终点并生成临时轨道，显示吸附目标与合法性
  → 释放：重新计算终点，验证长度、端口容量和几何约束
  → 成功：一次提交轨道及相关连接，一次写历史
  → 失败或取消：丢弃临时轨道，文档与历史不变
  → 保持轨道工具，等待下一次绘制
```

第一版采用按下拖出再释放的绘制方式，不同时引入“点击起点、点击终点”的另一套行为。预览期间可使用临时 ID，正式提交时生成稳定 ID。

第一版从端口开始绘制时，只允许连接空闲兼容端口。按在线段内部不自动创建分支；如果后续支持切分，应把切分、原有引用更新与新轨道创建组合成一次事务。

### 场景二：移动已连接道岔

```text
按下道岔主体：记录原始文档、选择集和起始图纸坐标
  → 超过拖动阈值：进入移动预览
  → 根据总位移生成候选道岔几何
  → 文档编辑模块更新相连轨道端点，得到整体候选文档
  → 渲染候选替换受影响对象，不叠画两份相同对象
  → 释放：再次验证并一次提交全部变化
```

如果联动导致轨道零长度或不满足约束，预览显示无效原因，释放时放弃本次移动。只更新明确支持的连接组合；不沿网络无限传播移动。Esc 应同时丢弃道岔和所有关联轨道的预览。

### 指针捕获与异常收尾

建议 Web 实现使用 Pointer Events。有效 pointerdown 后调用 setPointerCapture(pointerId)，仅处理当前手势的指针，使指针移出画布后仍能收到移动和释放事件。

有捕获时，普通 pointerleave 不结束手势。画布外释放依然走正常释放流程，并按是否允许目标位置决定提交或拒绝；pointercancel、窗口失焦或未正常结束时的 lostpointercapture 则取消。

统一 finish/cancel 入口要能重复调用而不重复提交：先将会话标记为结束并清理预览，再释放捕获。正常释放捕获产生的 lostpointercapture 发现已无活动会话时直接返回。若捕获失败，则取消启动，避免留下无法收尾的拖动。

### 一次操作如何只撤销一次

历史记录只发生在文档编辑模块接受一个有效且有变化的提交之后。mousemove 只更新候选，点击选择、平移、取消及无效释放都不新增文档历史。

候选始终从手势开始时的文档计算，避免将总位移重复累加。第一版手势期间禁用其他文档修改及撤销重做；Esc 取消后再执行其他编辑，避免以过期基线覆盖新文档。

### 验收场景

- 未超过阈值的点击只选择对象，不误移动。
- 连续多次移动事件仍只有一个候选操作，释放只生成一次历史。
- 在画布外释放能结束手势，再移动鼠标不会继续拖图元。
- Esc、失焦、pointercancel、异常丢失捕获均能清理预览并恢复选择。
- 正常结束后再收到 lostpointercapture，不会回滚刚提交的修改或重复提交。
- 无效轨道或无效联动移动不会改变文档和重做栈。
- 移动道岔后一次撤销，同时恢复道岔和相连轨道。
- 只读模式允许选择和平移，拒绝图元编辑意图。

## 15. 渲染管线、图层与重绘调度

> **参考源与适用范围：** 参考 [UIManager.java](../../src/com/lushprojects/circuitjs1/client/UIManager.java) 的 repaint、updateCircuit 与 [Graphics.java](../../src/com/lushprojects/circuitjs1/client/Graphics.java)。下面的独立场景渲染、requestAnimationFrame 调度和语义图层为新增设计。

渲染入口建议接受 document、viewport、selection、preview、theme、可选 runtimeState。渲染不修改文档，不生成历史，不在 draw 中修复拓扑。

绘制顺序统一为：背景与网格 → 轨道 → 设备 → 名称 → 诊断 → 选中与手柄 → 吸附和拖动预览。文档内同层对象使用稳定次序，命中重叠对象时按相同层级逆序处理。

一次变化只请求一次待执行帧；输入事件更新最新预览，多次移动合并为下一帧显示。静态编辑无变化时不持续重绘；运行状态动画单独请求帧，不将动画帧当作业务时间步。

图元与关联轨道的预览替换相应原对象；原对象可显示淡色轮廓，但不能把相同高亮实体重复画两次。绘图使用 save/restore 管理状态，单个图元不可泄漏变换、颜色和线宽。

第一版可用一个 Canvas，后续只有背景重画或运行状态叠加成为实测瓶颈时才拆层。轨道实体宽度可按图纸单位变化，手柄和操作提示按 CSS 像素保持可操作尺寸。

派生几何在绘制前就应可用，首次命中不能依赖先画一帧。明确普通、悬停、选中、错误、锁定和运行未知等样式的优先级；业务与编辑状态可以叠加，例如占用区段上仍要看清选中轮廓。字体或样式度量变化时使文字范围缓存失效，用户文字始终作为文本绘制。

**验收：** 高频指针移动不会无限排队；暂停后仍可编辑；改变主题不改文档；导出与屏幕共享几何但不共享临时交互状态。

## 16. 几何算法与布局约束

> **参考源与适用范围：** 参考 [CircuitElm.java](../../src/com/lushprojects/circuitjs1/client/CircuitElm.java) 的 interpPoint、lineDistanceSq、setBbox，以及 [Rectangle.java](../../src/com/lushprojects/circuitjs1/client/Rectangle.java)。站场允许的线形及约束求解策略需新增。

先实现无 UI 依赖的函数：点到线段距离、线段投影参数、包围盒并集/相交、旋转、镜像、点在线段内部的判定。统一 epsilon 及单位，区分模型连接容差和屏幕命中容差。

点 P 到线段 AB 的投影参数：`t = clamp(dot(P-A, B-A) / dot(B-A, B-A), 0, 1)`。若 AB 长度近零，先按退化线段处理，不执行除法。由 `Q=A+t(B-A)` 得到最近点及距离。

第一版将允许的轨道方向作为配置明确，例如水平、垂直或规定斜向，不默认所有设备都允许任意角度。约束流程为候选生成 → 吸附 → 几何检查 → 引用与拓扑检查，不做每个模块都偷偷修正一次的连锁调整。

只对当前操作能解释的局部几何进行自动调整。若移动要求网络中无限多对象联动，则拒绝并提示断开或扩展选择集，避免第一版引入通用约束求解器。

**验收：** 零长度、共线、重合、反向端点、负坐标和旋转后的包围盒均有明确结果；函数结果不依赖画布是否已绘制。

## 17. 属性面板与描述信息

> **参考源与适用范围：** 参考 [EditInfo.java](../../src/com/lushprojects/circuitjs1/client/EditInfo.java) 与 [EditDialog.java](../../src/com/lushprojects/circuitjs1/client/EditDialog.java)。字段键、纯描述结构、隔离草稿及关联校验为新增设计。

每种设备提供属性描述：key、label、type、unit、readOnly、取值范围、选项和帮助文本。例如道岔包含 name、rotation、handedness、length；内部 ID 只读。使用稳定字段 key，不依赖第几个输入框。

表单保留字符串草稿，允许输入过程出现暂时不完整的数字。应用时执行解析、有限值与范围检查，再提交一个修改属性意图。修改道岔尺寸可能带动连接轨道，必须经文档模块完成关联更新。

字段描述与实际控件分开，标签用翻译 key，数据仍按稳定字段 key 访问。显示单位和存储单位分别约定，空字符串、缺失值和零不混为一谈；字段错误带 key 和设备 ID。应用失败保留草稿供修改，文件保存内部数值，避免写入本地化显示字符串。

第一版采用“应用/取消”的独立草稿：取消丢弃尚未应用的数据；应用成功后建立新的基线。明确提示已应用修改不会因随后关闭面板而自动回滚。

多选时只展示类型兼容的共同字段；不一致显示“多个值”，不能显示为零或空字符串后误写所有对象。批量赋值作为一次事务，任何对象不满足约束时整组拒绝，并定位失败对象。

批量 patch 只包含用户明确修改的字段，不用未填写项覆盖其他值。属性描述可声明范围和选项，但几何、引用及编号规则仍由文档校验执行，不能仅依赖输入控件。

**验收：** 中文名称可正常输入；输入框 Delete 不删除图元；非法数字不污染文档；改名不改变 ID；属性修改可完整撤销。

## 18. 拓扑索引、轨道区段与一致性

> **参考源与适用范围：** 参考 [SimulationManager.java](../../src/com/lushprojects/circuitjs1/client/SimulationManager.java) 的 makeNodeList、calculateWireClosure、findUnconnectedNodes。以下显式端口图、业务区段和独立验证器是站场新增设计。

以 PortRef 为节点，Connection 为设备间连接边；设备内部通路为另一类边。例如轨道 start↔end，道岔 common↔normal 或 common↔reverse。内部通路携带条件，不把道岔三个端口直接合并成一个节点。

从文档派生 byId、portsByElement、connectionByPort 和邻接索引；加载或事务提交后更新。索引是可重建缓存，不在文件中另存一份可独立修改的“真实连接”。端口 key 用结构化二级映射或可靠编码，避免手工拼接产生碰撞。

结构验证检查 ID 唯一、端口存在、容量、重复边、端口位置重合、设备属性合法和引用有效。未连接端口可能是预期边界，应区分“错误”和“提示”，支持显式的终端或开放边界语义。

轨道区段作为引用多条线段的业务记录后加，不与图形分组混用。若新增 `sections`，应同步定义其 ID、名称、成员线段、边界设备和删除/切分规则，并通过文件版本迁移引入；不能仅在界面颜色中隐含区段。

**验收：** 视觉交叉不自动连接；旋转不改变端口身份；删除不留引用；从相同文档重建拓扑得到相同连接结果。

## 19. 条件路径查询与候选路径高亮

> **参考源与适用范围：** 参考 [FindPathInfo.java](../../src/com/lushprojects/circuitjs1/client/FindPathInfo.java) 的 visited、findPath、checkElm；不复用其电气规则。铁路方向、道岔条件与路径返回结构为新增设计。

输入包括起终端口、查询模式、方向限制和可选运行状态。输出包含经过的设备/端口、道岔条件、耗时或代价及失败原因。默认先提供拓扑路径预览，不将其直接称为已经校验的联锁进路。

查询模式应区分：按当前道岔状态查可达路径，或在静态设计中查可选路径并返回所需条件。若允许同次搜索选择设备状态，已选择的道岔条件也要进入搜索状态，防止前后要求同一道岔处于冲突状态。

无权最短路径用 BFS；带长度或其他非负权重时用 Dijkstra。只有存在可解释、不会高估实际剩余代价的启发式时才考虑 A*。visited 的键应包含影响通行的端口、方向及条件，不能只记设备 ID。

限制最大展开量、返回数量和耗时，先返回一条可解释路径，避免直接枚举复杂图的全部简单路径。结果仅作为派生高亮，不改变原图元样式数据。

请求带 documentRevision；依赖运行状态时还带运行状态版本。第一版先重建邻接表，确需缓存后再按连接、设备内部通路和相关条件变化使其失效。查询支持中断，反向查询遵循方向约束，设备改名不改变可达性。

**验收：** 环路可终止；道岔定位/反位得到不同结果；方向不符返回不可达；旧文档计算结果不会覆盖新修订的画面。

## 20. 几何自动布线与辅助对齐

> **参考源与适用范围：** 参考 [WireRouter.java](../../src/com/lushprojects/circuitjs1/client/WireRouter.java) 的 initGrid、routeWire、compressPath。固定端口、站场线形与搜索预算需新增。

输入为起终端口、图纸障碍、允许方向、最小段长和搜索范围；输出为折点或明确的不可达结果。固定设备及其端口保持不动，不能为了得到路径而修改业务连接。

先尝试直连和少量折点模式，再在有限局部网格搜索。转弯有代价时状态包含方向；支持斜向时补充穿越障碍角点检查。路径压缩后重新验证障碍与最小段长，不只验证压缩前格点。

穿过已有轨道不自动创建连接；是否允许视觉交叉由布局规则决定。示意图上折线代表一条轨道还是多个可连接线段，必须在输出转换时明确，必要的切分与 ID 分配一次提交。

第一版只做网格对齐、端口吸附及手动绘制即可。自动布线作为后续可选工具，不能成为打开文件或普通拖动的前提。

障碍可按符号间距膨胀，同时为端口保留合法出线通道，图元接入可对照 [RoutedWireElm.java](../../src/com/lushprojects/circuitjs1/client/RoutedWireElm.java)。增加斜向邻居时，应重新确定移动代价与启发式，不能无条件沿用四向搜索的曼哈顿距离。结果区分成功点列与 blocked、budget、invalid 等失败原因；搜索超预算及时退出，不阻塞指针交互。

**验收：** 无路时有界退出；不穿越禁止区域；端口保持准确；同一候选输入可得到稳定结果；提交后可一次撤销。

## 21. 批量编辑、分组与模板

> **参考源与适用范围：** 参考 [CommandManager.java](../../src/com/lushprojects/circuitjs1/client/CommandManager.java) 的 prepareFlip、rotateCW/CCW、doPaste，及 [CustomCompositeModel.java](../../src/com/lushprojects/circuitjs1/client/CustomCompositeModel.java)。普通分组、模板版本和铁路语义变换需新增。

多选移动、旋转和镜像使用共同基准。旋转时同时处理位置、方向、端口几何及信号朝向；镜像时明确道岔开向如何变化。若符号或业务类型不支持该变换，应拒绝而不是仅翻转像素。

选择集之外存在连接时，批量变换仍按统一联动规则处理；不能只变换选区内几何而留下断开的显式连接。对齐和等间距操作也使用同一事务入口。

相连设备同时位于选区时，连接只维护一次；统一吸附共同锚点或位移，不逐个吸附破坏布局。镜像可改变道岔开向，但不能按端口数组位置重新命名 common/normal/reverse。若后续增加设备锁定，允许选择和查看，包含锁定对象的变换则整组拒绝并说明原因。

分组只表示一起选择和操作，不改变拓扑。模板表示可重复插入的一组设备与内部连接。第一版插入模板后展开为独立对象，所有 ID 重新分配，后续修改模板不追溯改变已插入实例。

模板定义保存版本、局部坐标、设备及内部连接，编号使用占位值，实例化时生成或要求补齐，避免重复编号。临时选择集只存在会话；若增加持久分组，应单独保存组 ID 和成员 ID，不让分组承担区段通路语义。

如果以后支持共享实例，应增加模板 ID、版本、实例局部变换和更新策略，再引入上下文编辑。不要直接套用电气子电路的端口折叠语义。

共享实例可以显式暴露端口，未暴露的内部端口不接收外部吸附，并在文档携带必要定义快照以应对缺库。升级时展示端口变化及引用修复计划，验证候选后提交。这些实例边界规则只在引入共享实例后使用，第一版展开对象仍遵循普通设备的连接规则。

**验收：** 镜像两次恢复几何和设备语义；旋转四次恢复；模板副本无 ID 冲突；内部连接重新映射，外部连接不被意外复制。

## 22. 文档版本、保存确认与迁移

> **参考源与适用范围：** 参考 [XMLSerializer.java](../../src/com/lushprojects/circuitjs1/client/XMLSerializer.java)、[XMLDeserializer.java](../../src/com/lushprojects/circuitjs1/client/XMLDeserializer.java)、[LoadFile.java](../../src/com/lushprojects/circuitjs1/client/LoadFile.java) 与 [preload.js](../../app/preload.js)。以下暂存加载、迁移及保存确认协议均需新增。

文件使用稳定格式名和 schemaVersion。初始数据结构见第 4 节，增加业务记录时升级版本，并提供纯转换函数 v1→v2→v3；不在图元 draw 中修复旧数据。未知新版本默认拒绝，保留原文件与当前文档。

加载过程：读取 → 解析 → 迁移 → 字段检查 → 引用检查 → 构建派生几何/拓扑 → 整体替换。每步失败返回阶段、字段路径和对象 ID，不留下部分对象。文件大小、对象数量、嵌套深度和数值范围都有可配置上限。

文本、文件、模板和外部调用共用解析校验入口。替换导入成功后重置旧文档历史和运行态；合并导入则重映射 ID 与内部引用，并作为一次编辑事务。异步解析带 requestId，连续选择文件时仅最后一次有效请求可以替换文档。

文档使用单调递增 revision 区分提交；dirty 则与最后确认保存的内容基线比较，不能仅用 revision 不相等判断，否则撤销回已保存内容仍会误报未保存。

保存时捕获文档快照和内容标识，异步写入完成才确认该内容已保存。如果保存期间用户继续编辑，保存成功也不能清除新内容的 dirty。失败保持 dirty，并显示重试入口。

浏览器普通下载通常只能确认已生成并交给下载流程，不能声称已验证磁盘写入；桌面或支持文件句柄的适配器应返回明确完成/取消/失败结果。桌面临时文件替换方案也需处理目标平台的实际行为。

保存命令显示进行中状态，重复触发不并发覆盖同一目标。只有另存为成功后才更新文档绑定路径，取消或失败保留原路径。revision 用于关联请求及检查过期结果，是否已保存仍按内容基线判断。

**验收：** 旧格式可迁移；未知格式不破坏当前文档；异步保存不错误清除 dirty；取消保存不被视为成功。

## 24. 命令入口、历史与修订控制

> **参考源与适用范围：** 参考 [CommandManager.java](../../src/com/lushprojects/circuitjs1/client/CommandManager.java)、[UndoManager.java](../../src/com/lushprojects/circuitjs1/client/UndoManager.java)。统一提交接口、结构化结果和修订校验为新增设计。

工具、菜单、属性面板、键盘和外部接口都提交相同编辑意图，不分别直接写文档。例如：

```ts
type EditIntent =
  | { type: "move"; ids: string[]; delta: Point }
  | { type: "connect"; a: PortRef; b: PortRef }
  | { type: "delete"; ids: string[] };

// patch 的结构应按设备类型单独约束，不接受任意字段覆盖。
// commit(intent, expectedRevision) → success | noChange | failure
```

入口在内部完成目标解析、几何变换、引用维护、验证、文档替换、历史更新、缓存失效与通知。所有调用者无需记住“先改图元，再改连接，再写历史”的顺序。

菜单、工具栏、快捷键与外部调用共享稳定命令 ID，命令集中提供 canExecute 和 execute。执行时仍检查只读、选择集与活动工具等上下文，不能只靠按钮灰显。删除、保存等命令执行后结束；切换绘制工具只改变后续输入行为，不创建文档历史。快捷键配置按命令 ID 保存，并检测同一上下文中的冲突，现有配置界面可参考 [ShortcutsDialog.java](../../src/com/lushprojects/circuitjs1/client/ShortcutsDialog.java)。

设备类型搜索与已放置设备搜索分别提供：前者启动放置工具，后者返回稳定设备 ID，设置选择并定位视口。改名不改变搜索结果对应的设备身份。

expectedRevision 不匹配时拒绝过期意图或重新计算；不静默覆盖。分析、搜索、异步文件解析等结果携带输入修订，返回后若已过期则丢弃。第一版不进行多人合并。

快照历史设置内存或条数上限，避免长期编辑占满内存。连续方向键移动可按同一会话合并，但选择变化或其他操作后必须断开合并。历史中不混入运行状态帧。

提交明确返回成功、无变化或带诊断的失败；失败保留文档、revision、历史和重做栈。Undo/redo 从受控入口切换快照，清理旧对象的悬停和预览，选择集按当前有效 ID 恢复或清理。历史淘汰不改变当前文档，加载新文档不沿用旧文档会话。

**验收：** 同一编辑通过菜单与快捷键得到相同文档；失败不改历史和重做栈；无变化不发文档修改事件；撤销重建后的派生缓存一致。

## 25. 运行状态、事件时间线与回放

> **参考源与适用范围：** 参考 [ScopePlot.java](../../src/com/lushprojects/circuitjs1/client/ScopePlot.java) 的采样与循环缓冲区、[SimulationManager.java](../../src/com/lushprojects/circuitjs1/client/SimulationManager.java) 的时间步及 [JSInterface.java](../../src/com/lushprojects/circuitjs1/client/JSInterface.java) 的时间步回调。铁路状态与回放语义需另建，电气求解不直接迁移。

后续运行数据以设备 ID 索引，与设计文档分开：轨道区段占用、道岔显示状态、信号显示等均为独立快照或事件流。编辑不应意外覆盖运行数据，文档版本改变时要检查设备映射是否仍有效。

后续引入演示时，先验证并固定 documentRevision，最初的演示版本禁止同时修改设计。状态缺失显示未知，演示失败保留设计文档；退出时丢弃运行态或另存场景，加载其他文档清理旧状态和订阅。外部状态先经适配校验，再进入运行模块，不直接修改设备几何。

事件记录包含序号、时间、设备 ID、类型和载荷。使用固定初始快照加有序事件得到回放结果；真实时间、模拟时间与绘图帧时间分别表示。重复序号不重复应用，缺失序号显示不完整状态。

事件还可记录旧值、新值和来源，按 `(time, sequence)` 处理，明确时间单位、同一时刻顺序、暂停和单步语义。外部乱序按协议处理，不无提示改写历史；回放时暂停实时输入或隔离通道，避免混合两种时间。

有限环形缓冲用于近期观察；需永久回放时另存事件文件和索引，不能把覆盖式缓冲当作完整记录。回放高亮是视图输出，不产生设备编辑历史。

缓冲淘汰时显示保留范围；长记录可定期保存运行快照，从最近快照继续重放以支持快速跳转。时间线按设备和事件类型过滤，点击事件定位设备；设备已删除时仍保留历史标签供查看。连续测量可用 min/max 分桶，占用等离散状态使用区间或状态阶梯。

导出事件文件包含文档 ID、设计版本、时间单位及场景版本，不以设备名称作为唯一引用。清空监视数据不删除设备，撤销设计编辑也不撤销已经接收的运行事件。验收时比较跳转回放与从头重放的结果，并检查缓冲回绕是否出现旧槽位。

**验收：** 相同初态和事件序列得到相同状态；暂停回放可继续查看图纸；未知设备事件可诊断；帧率变化不改变业务事件顺序。

## 26. 性能、空间索引与后台计算

> **参考源与适用范围：** 参考 [PerfMonitor.java](../../src/com/lushprojects/circuitjs1/client/util/PerfMonitor.java)、[UIManager.java](../../src/com/lushprojects/circuitjs1/client/UIManager.java) 的耗时分段与 [MouseManager.java](../../src/com/lushprojects/circuitjs1/client/MouseManager.java) 的遍历命中。空间索引、Worker 和修订缓存为新增能力。

先测量加载、几何构建、命中、预览、绘制、拓扑分析和保存各自耗时。使用小型样例和生成的大型图纸，记录设备数、连接数、视口尺寸、dpr 与机器环境；性能目标在目标设备上测定，不把某个帧率视为天然保证。

基准补充中型站场和密集重叠对象，报告指针输入到显示的延迟及各阶段耗时，不只给平均 FPS。无交互及运行状态变化时不持续重绘，连续输入只保留最近候选，避免无限积压任务。

优化顺序建议为：合并帧请求 → 几何缓存 → 按视口裁剪 → 命中空间索引 → 按实测拆分后台任务。索引选型随数据量与更新模式决定，先让“按矩形找候选”成为小接口。

几何缓存键包括图元修订；文字包围盒还受字体、字号、主题相关度量影响。移动、改名、旋转、删除、撤销和加载后更新索引，不能只在第一次绘图时创建。

缓存可由设备 ID、几何版本和符号样式版本共同定位，平移画布不重算设备局部几何。校验先采用全量实现，确认正确后再按受影响设备及引用邻居增量检查；存储防抖也必须保留最后一次成功提交的版本。

耗时搜索可移至 Worker，传可序列化快照，不共享 Canvas 或 UI 对象。结果携带 revision 和 requestId，支持取消；已过期响应不得更新当前高亮。

**验收：** 缓存与无缓存计算结果一致；移出视口的对象仍存在文档；撤销后可准确命中；旧任务不会覆盖新结果；长期拖动不持续增长资源。

## 27. 外部接口与平台适配

> **参考源与适用范围：** 参考 [JSInterface.java](../../src/com/lushprojects/circuitjs1/client/JSInterface.java)、[websocket/README.md](../../websocket/README.md)、[main.js](../../app/main.js) 与 [preload.js](../../app/preload.js)。StationEdit 外部契约及受限文件适配为新增设计。

第一版按需要提供 loadDocument、exportDocument、dispatchEdit、selectElements、fitView、subscribe 等少量能力。读接口返回快照，不暴露内部可变对象；写接口仍经过文档命令入口和只读检查。

订阅返回取消函数，关闭编辑器或切换文档时清理。事件区分文档提交、选择变化与运行状态，不让外部每帧导出整份文件。异步请求返回结构化成功、取消或错误。

初始化完成后才接收命令。事件可携带实例 ID、documentId、revision、requestId 和类型，销毁时取消未完成请求。回调抛错不能破坏内部事务，写请求需按协议识别重复请求，避免重试重复创建设备。

浏览器下载与桌面文件读写是可替换的平台适配器，不进入几何模块。桌面只暴露需要的读写方法和结果，不让图元直接操作文件系统。嵌入页面时约定消息版本、来源和允许命令，避免无条件执行任意消息。

跨 iframe 使用 postMessage 时同时核对来源窗口、明确的 origin 和消息结构。文件桥接使用明确 IPC 和参数检查，不向页面暴露任意文件系统对象。

WebSocket 桥接可用于之后的状态接入；它与多人编辑不是同一个功能。若未来要协作，再明确服务端权威、版本冲突和离线合并策略，第一版不提前引入。

**验收：** 外部删除与界面删除使用相同约束；卸载后无残留订阅；文件取消不改变 dirty；未知命令有明确错误。

## 28. 快捷键、触屏、主题与可访问性

> **参考源与适用范围：** 参考 [UIManager.java](../../src/com/lushprojects/circuitjs1/client/UIManager.java) 的 onPreviewNativeEvent、[Toolbar.java](../../src/com/lushprojects/circuitjs1/client/Toolbar.java)、[Locale.java](../../src/com/lushprojects/circuitjs1/client/util/Locale.java) 与 [MouseManager.java](../../src/com/lushprojects/circuitjs1/client/MouseManager.java) 的触屏适配。下面是新编辑器统一策略。

快捷键按上下文分发：输入框/中文输入合成 → 对话框 → 活动工具 → 全局命令。composition 期间不触发设备快捷键；Delete、方向键和 Ctrl/Cmd+Z 在文本输入中优先执行文本操作。只读检查放在编辑入口，而不只隐藏按钮。

第一版以鼠标和键盘为主，Pointer Events 统一指针生命周期；增加双指平移缩放时先取消已有编辑手势，避免单指画轨道过程中第二指变成误创建。提供方向键微调、Esc 取消和可见焦点。

主题使用语义颜色：轨道默认、占用、候选路径、选中、错误、禁用等，不在每个 draw 中写颜色常量。状态不能仅靠颜色表达，还可使用图标、线型、标签及属性面板说明。

界面文案用稳定翻译键，业务设备名称保持用户输入原文。Canvas 之外提供可搜索设备列表，允许键盘选择、定位并编辑属性；工具按钮与错误列表具有可读名称。

触摸阈值、命中容差和手柄尺寸按指针类型配置，不改变图纸几何。窄屏可将属性面板改为抽屉，保留当前工具和取消入口；布局变化时可取消活动手势，避免基线失效，不能因此改动设备位置。对话框关闭后焦点回到触发位置，工具栏明确标记当前工具；键盘操作应能创建样例设备，文字放大后面板仍可用。

### 资源、语言与示例加载

> **参考源与适用范围：** 启动资源参考 [circuitjs1.java](../../src/com/lushprojects/circuitjs1/client/circuitjs1.java) 的 loadLocale、[Menus.java](../../src/com/lushprojects/circuitjs1/client/Menus.java) 的示例列表和 [QueryParameters.java](../../src/com/lushprojects/circuitjs1/client/QueryParameters.java)。以下加载状态、翻译键和竞态处理为新增设计。

启动顺序为用户设置 → 必要字体和语言 → 初始化编辑器 → 打开指定或空白文档，显式区分 loading/ready/error。语言和可选示例失败允许回退到空白编辑，必要资源失败则显示可重试状态。请求带 requestId，连续选择示例时只接受最后一次结果，默认示例晚返回不得覆盖正在编辑的文档。

示例清单记录 ID、标题 key、路径、格式版本及说明，与普通文件共用解析校验入口，打开前处理未保存修改。验证语言加载失败仍可编辑、中文名称往返无损、晚返回示例不覆盖新文档。

**验收：** 中文输入无误触快捷键；深浅主题仍能辨识状态；键盘可完成选择和属性修改；重复按键不重复执行不可重复命令。

## 29. 自动恢复、诊断与可观测性

> **参考源与适用范围：** 参考 [UndoManager.java](../../src/com/lushprojects/circuitjs1/client/UndoManager.java) 的恢复快照、[CirSim.java](../../src/com/lushprojects/circuitjs1/client/CirSim.java) 的异常处理、[UIManager.java](../../src/com/lushprojects/circuitjs1/client/UIManager.java) 的错误指示。按文档恢复、修订标记及结构化诊断为新增设计。

每次成功提交后标记待恢复保存，在防抖后持久化已提交文档；不会写拖动候选。按文档 ID 保存内容、格式版本、时间和校验信息，并保留上一份可用恢复副本。恢复写入成功不等于用户已经保存工程文件。

用户设置、工程文件、恢复草稿和撤销历史各有生命周期。小型语言/网格/快捷键设置可用带版本的 localStorage 记录，较大恢复草稿可用 IndexedDB；草稿附带 revision、应用版本和 sessionId，历史第一版不跨重启保存。多窗口检测同文档草稿冲突，不能用一个全局 key 相互覆盖；退出时的异步保存不能作为唯一保障。

存储不可用、配额不足或写入失败应提示恢复能力受限，但编辑器仍能使用并手动导出。打开文件前若存在未保存内容，走保存/放弃/取消选择；不自动用恢复数据覆盖用户刚选择的文件。

诊断结构建议为 code、severity、message、elementIds、portRefs、fieldPath。界面可点击错误定位设备；重复诊断按稳定键合并。日志记录操作类型、revision、耗时和失败阶段，避免默认记录整份工程内容。

渲染错误与文档校验错误分别处理；单个符号绘制失败可显示替代框和诊断，不能把坏对象静默从文件删掉。

### 校验层次与执行时机

> **参考源与适用范围：** 分层思路参考 CircuitElm.validate/creationFailed、SimulationManager.validateCircuit/stop 和 [FindPathInfo.java](../../src/com/lushprojects/circuitjs1/client/FindPathInfo.java)。以下站场规则、错误级别及执行策略需新增。

| 层次 | 示例 | 处理 |
| --- | --- | --- |
| 文件结构 | 缺失类型、非法数值、不支持版本 | 拒绝加载，保留原文档 |
| 身份与引用 | ID 重复、设备或端口不存在 | 拒绝候选提交 |
| 几何 | 零长度、无效尺寸、连接端口不重合 | 拒绝当前编辑 |
| 业务配置 | 重复编号、关联方向无效 | 按具体规则拒绝或警告 |
| 完整性提示 | 明确允许的未连接边界端口 | 提示确认，不一律判错 |

规则返回诊断，不直接弹窗或修改对象；UI 负责列表、字段提示和定位。第一版可全量校验，后续提交时检查受影响对象和邻居，保存或显式检查时运行全量。异步诊断附带 revision，旧结果不得覆盖新结果；点击已经删除设备的诊断时安全忽略并刷新。诊断 code 保持稳定，文案可用 messageKey 翻译。

### 受限表达式与自定义规则

> **参考源与适用范围：** 参考 [Expr.java](../../src/com/lushprojects/circuitjs1/client/Expr.java) 的解析与 eval、[CustomLogicModel.java](../../src/com/lushprojects/circuitjs1/client/CustomLogicModel.java) 的 parseRules。下面的站场规则接口、版本与工作量限制为新增设计。

编号唯一、端口容量等固定约束先用普通代码实现。只有确需用户配置时才增加小型表达式语言；几何约束、文档校验和运行演示条件分别定义，静态校验不能修改文档。

规则记录 ID、版本、输入字段和文案 key，接收只读属性与必要关系，输出布尔值或诊断。文本解析一次生成树，先检查变量和类型，限制长度、节点数及求值工作量，不允许访问文件、网络和应用全局对象。缺失值、除零、非有限结果和预算超限返回明确错误。

运行规则绑定 runtime 快照，记录规则版本和事件顺序以保证回放。验收覆盖优先级、括号、未知变量、缺失属性、除零及预算超限，错误能定位规则 ID；同输入同版本输出一致，表达式不能绕过事务修改设备。

**验收：** 恢复只包含已提交内容；坏恢复副本不覆盖好文件；写入失败可见且可重试；诊断能定位对象而非只弹出“失败”。

## 31. 构建、部署、桌面与离线

> **参考源与适用范围：** 参考 [build.gradle](../../build.gradle)、[test.sh](../../test.sh)、[main.js](../../app/main.js)、[service-worker.js](../../war/service-worker.js) 与 [circuitjs.html](../../war/circuitjs.html)。新项目的工具链按选定语言配置，下面定义的是应满足的工程能力。

开发命令、生产构建、测试、预览与产物目录写入项目 README；依赖版本可重复安装。绘图核心不依赖开发服务器路径，资源使用统一 base URL，验证根路径和子目录部署。

CI 按语言执行类型或编译检查、相关行为测试与生产构建；浏览器端到端验证在需要覆盖输入流程时运行。发布产物包含字体、符号库、样例和所需脚本，不能只复制入口 HTML。

运行时版本、依赖版本和锁文件进入版本控制。流水线从锁定依赖安装开始，经过检查、测试、打包、资源完整性检查和预览主流程，记录 commit、应用版本及 schema 版本，生成可追踪产物。最终资源还需核对语言和可选 Worker，不打包用户恢复草稿或开发测试数据。保留最近可用产物，回退应用时仍提示较新工程格式的不兼容。

桌面版复用文档与几何模块，平台差异集中在文件对话框、保存确认和窗口生命周期。多窗口各持有自己的文档会话，保存同一路径时提示外部变更，避免静默覆盖。

起步先交付 Web，确需桌面时再加文件适配。窗口各自维护文档 ID、路径和 revision，不共享一个可被覆盖的 lastSavedFilePath；具体 Electron 配置按采用版本验证，不直接复制当前仓库设置。

离线应用缓存与用户工程存储分别管理。只有明确需要离线时才加入 Service Worker，版本更新时验证资源完整性、旧缓存清理、首次加载失败与未保存文档保护。

缓存清单由最终构建产物生成，使用正确资源基址并标明版本。更新可用时提示先保存，不能在活动编辑时强制刷新；更新失败继续使用已验证的旧资源，避免混用不同版本脚本和符号。验收包含断网后新建编辑、首次缺少资源的明确提示和应用更新不丢已提交草稿。

**验收：** 干净环境可按说明构建；生产资源可加载；子路径不丢字体；应用更新不会自动清空用户工程；桌面保存失败正确反馈。

## 32. 实现顺序与完成定义

> **参考源与适用范围：** 综合本文各节对应源码形成的实施计划，不是 CircuitJS 原有开发计划；第 11 节是第一版简表，本节补充完整技术链路。

| 阶段 | 主要交付 | 依赖与验证 |
| --- | --- | --- |
