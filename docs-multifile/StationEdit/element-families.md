## 建议的设备族

| 设备族 | 初始类型 | 需要表达 |
| --- | --- | --- |
| 轨道几何 | 线段、后续折线 | 端点、走向、连接 |
| 连接设备 | 简单道岔、后续复杂交叉设备 | 稳定端口与内部通路 |
| 信号设备 | 简单信号机 | 朝向、轨道关联、显示配置 |
| 分界与辅助标记 | 绝缘节、边界等 | 业务作用及关联，不仅是图案 |
| 文字与装饰 | 文字、框线、底图 | 布局与资源，不参与轨道通行 |

第一版只实现已约定的线段、简单道岔、信号机和文字。其他类型按真实需求加入，不用一个任意 shape 加字符串属性来替代明确设备语义。

## 新类型落地步骤

1. 定义持久字段、ID、版本和默认值。
2. 定义局部几何、端口和可编辑手柄。
3. 实现绘制、命中、平移及支持的变换。
4. 声明属性并加入类型注册和放置工具。
5. 定义连接兼容、内部通路及删除引用规则。
6. 补文件往返、复制、撤销和样例验收。

如果设备切分轨道，需要明确原轨道 ID、区段归属与信号关联怎样迁移；切分与新设备放置是一次事务。

## 外部资源

底图或图标用资源 ID 关联，保存工程时明确嵌入还是外链；缺失资源保留占位及设备数据。不要在每次绘制中重新请求网络资源，也不要把临时内存缓存当成可移植工程备份。

## 验收

新类型接入后通用选择和历史流程不需要新增特例；未知版本拒绝加载而不丢数据；外部资源缺失不会破坏轨道拓扑。
