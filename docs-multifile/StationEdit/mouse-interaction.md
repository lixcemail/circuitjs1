## 鼠标交互与工具状态机

> **参考源与适用范围：** 参考 [MouseManager.java](../../src/com/lushprojects/circuitjs1/client/MouseManager.java) 的 mouseMode、tempMouseMode、onMouseDown、mouseDragged、onMouseUp、endDrag、onMouseOut，以及 [UndoManager.java](../../src/com/lushprojects/circuitjs1/client/UndoManager.java) 的快照历史。显式状态、指针捕获、隔离预览、取消回滚及统一事务提交均为本站场方案新增设计。

### 工具与状态分别表示什么

工具回答“用户准备做什么”，状态回答“这次操作进行到了哪一步”。选择轨道工具不等于已经开始画轨道。

```text
工具：选择、画轨道、放道岔、放信号机、平移
状态：等待、按下待判定、拖动预览
```

第一版每次只允许一个指针手势；按下前可以切换工具，手势中切换工具先取消当前预览。按下时固定本次手势的目标和模式，不因鼠标经过其他设备而换目标。

### 输入、工具、文档各做什么

| 模块 | 职责 |
| --- | --- |
| 输入适配 | 事件坐标转换、pointerId、鼠标键、修饰键、指针捕获 |
| 工具 | 判断当前意图，管理状态和预览，提交编辑意图 |
| 几何与命中 | 返回候选目标、手柄、端口及吸附结果 |
| 文档编辑 | 维护连接、验证候选文档、原子提交和历史记录 |
| 渲染 | 绘制已提交文档、候选预览及交互提示 |

不要让每种图元各自注册鼠标事件。工具根据命中结果调用图元行为和文档编辑入口。

### 状态转换表

| 当前状态 | 输入 | 处理 | 下一状态 |
| --- | --- | --- | --- |
| 等待 | 主按钮按下 | 固定目标，记录原始文档、起始点和 pointerId，尝试捕获指针 | 按下待判定 |
| 按下待判定 | 移动未超过阈值 | 保留点击候选，不提交几何修改 | 按下待判定 |
| 按下待判定 | 移动超过阈值 | 根据工具与命中部位启动预览 | 拖动预览 |
| 按下待判定 | 主按钮释放 | 执行工具的点击行为，不创建零长度轨道 | 等待 |
| 拖动预览 | 指针移动 | 根据起始数据和总位移重算候选，显示吸附及无效原因 | 拖动预览 |
| 拖动预览 | 主按钮释放 | 以释放位置重算最终候选，验证并提交；失败则丢弃候选 | 等待 |
| 手势进行中 | Esc、pointercancel、窗口失焦或异常捕获丢失 | 丢弃预览，释放资源，保留已提交文档 | 等待 |

拖动阈值用 CSS 像素定义，例如先取 4 像素，再根据操作体验调整。有效性与最小轨道长度用图纸单位表达，两者不是同一个阈值。

### 选择工具的命中分发

建议优先考虑当前选中对象的手柄，其次主体，最后空白。连接工具则优先考虑兼容端口；命中优先级应与当前工具有关。

- 点中主体并释放：更新选择集；按住 Shift 时切换该图元的选择状态。
- 点中已选主体并拖动：移动当前选择集。
- 点中未选主体并拖动：以该图元为新的移动目标。
- 点中允许调整的手柄并拖动：进入对应几何调整。
- 空白处点击：清空选择；空白处拖动：框选，第一版采用包围盒完全包含规则。
- 拖动过程中保持命中目标固定，悬停变化只用于连接吸附等明确的候选查询。

几何预览取消不应遗留临时选择效果；手势记录开始时的选择集，取消时恢复。普通点击选择不进入文档撤销历史。

### 场景一：画一条轨道

```text
选中轨道工具
  → 按下：获取图纸起点，优先吸附可用端口，其次吸附网格
  → 拖动：计算终点并生成临时轨道，显示吸附目标与合法性
  → 释放：重新计算终点，验证长度、端口容量和几何约束
  → 成功：一次提交轨道及相关连接，一次写历史
  → 失败或取消：丢弃临时轨道，文档与历史不变
  → 保持轨道工具，等待下一次绘制
```

第一版采用按下拖出再释放的绘制方式，不同时引入“点击起点、点击终点”的另一套行为。预览期间可使用临时 ID，正式提交时生成稳定 ID。

第一版从端口开始绘制时，只允许连接空闲兼容端口。按在线段内部不自动创建分支；如果后续支持切分，应把切分、原有引用更新与新轨道创建组合成一次事务。

### 场景二：移动已连接道岔

```text
按下道岔主体：记录原始文档、选择集和起始图纸坐标
  → 超过拖动阈值：进入移动预览
  → 根据总位移生成候选道岔几何
  → 文档编辑模块更新相连轨道端点，得到整体候选文档
  → 渲染候选替换受影响对象，不叠画两份相同对象
  → 释放：再次验证并一次提交全部变化
```

如果联动导致轨道零长度或不满足约束，预览显示无效原因，释放时放弃本次移动。只更新明确支持的连接组合；不沿网络无限传播移动。Esc 应同时丢弃道岔和所有关联轨道的预览。

### 指针捕获与异常收尾

建议 Web 实现使用 Pointer Events。有效 pointerdown 后调用 setPointerCapture(pointerId)，仅处理当前手势的指针，使指针移出画布后仍能收到移动和释放事件。

有捕获时，普通 pointerleave 不结束手势。画布外释放依然走正常释放流程，并按是否允许目标位置决定提交或拒绝；pointercancel、窗口失焦或未正常结束时的 lostpointercapture 则取消。

统一 finish/cancel 入口要能重复调用而不重复提交：先将会话标记为结束并清理预览，再释放捕获。正常释放捕获产生的 lostpointercapture 发现已无活动会话时直接返回。若捕获失败，则取消启动，避免留下无法收尾的拖动。

### 一次操作如何只撤销一次

历史记录只发生在文档编辑模块接受一个有效且有变化的提交之后。mousemove 只更新候选，点击选择、平移、取消及无效释放都不新增文档历史。

候选始终从手势开始时的文档计算，避免将总位移重复累加。第一版手势期间禁用其他文档修改及撤销重做；Esc 取消后再执行其他编辑，避免以过期基线覆盖新文档。

### 验收场景

- 未超过阈值的点击只选择对象，不误移动。
- 连续多次移动事件仍只有一个候选操作，释放只生成一次历史。
- 在画布外释放能结束手势，再移动鼠标不会继续拖图元。
- Esc、失焦、pointercancel、异常丢失捕获均能清理预览并恢复选择。
- 正常结束后再收到 lostpointercapture，不会回滚刚提交的修改或重复提交。
- 无效轨道或无效联动移动不会改变文档和重做栈。
- 移动道岔后一次撤销，同时恢复道岔和相连轨道。
- 只读模式允许选择和平移，拒绝图元编辑意图。
